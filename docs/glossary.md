# 术语表

README 里用到的内部词，按出现的位置分组。每条给一句话解释，需要时标出实现在哪个文件。

英文 README 也链到这里；本文件按 `CONTRIBUTING.md` 的语言约定用中文写。

## 会话与线缆

**§N§**
工具结果上的序号标签。`ctx_reduce` 用它指定要回收哪一条，`ctx_expand` 用它取回原文。
编号在单个会话内单调递增，不重复使用。

**surface（线缆）**
宿主真正发给模型的那串消息。压缩、回收、发布都只改存储，真正改写 surface 发生在某个决策点，
不是想改就改。

**overlay**
宿主界面上浮在对话之上的那层东西。插件的遥测徽标和面板挂在里面。

**composer**
界面底部的输入框区域。没发出去的消息、附件、发送按钮都在这里；遥测胶囊贴在它上方。

**pre-step**
每次请求模型之前宿主调用的那个钩子。插件的绝大部分决策都在这里做：算压力、决定回收、
决定要不要跑 historian。

**flat/headless**
没有 Web/桌面界面的宿主形态：flat 指单一扁平 profile，headless 指没有 GUI。压缩接缝只在这两种
形态下有效，Web 与桌面端的 agent 跑在各自的 agent preset 里，profile 顶层的接管行碰不到它们。

**HMR**
宿主的模块热替换。开着的时候装完插件不用重启 profile。

## 回收

**回收带（reclaim band）**
一次允许真正改写 surface 的时机。`ctx_reduce` 只把条目排进队列，落地要等到下一个回收带——
因为改写 surface 会让缓存前缀失效，代价是实打实的钱。

**execute band**
压力过了执行阈值（默认 65%）之后进入的区间。historian 的产出在这个带内发布到 surface。

**execute / defer**
每个决策点的两种结果。`execute` 表示这一步就落地回收，`defer` 表示再等等。
`/ctx-report` 里的比例就是这两种的计数。

**tag**
见 `§N§`。内部表里一条 tag 对应"某会话里的某个工具结果"。

## 历史压缩

**historian**
做摘要的那个角色。它重放真实的历史前缀（保住 KV cache），产出摘要和事实；
只写存储，不动 surface。可以用独立模型路由，也可以跟随会话。

**compartment（压缩段）**
historian 产出的一段摘要，覆盖一段连续的历史事件。单数指一段，复数在存储里是一张表——
README 里只解释单数这个概念，不列内部表名。

**四层摘要（four summary layers）**
historian 一次调用产出的 p1–p4 四档详略，是同一份摘要的四个粒度：
p1 全细节（决策及理由、精确路径与标识符）、p2 要点（做了什么、还差什么、关键约束）、
p3 几句概括当前目标与状态、p4 一两句最耐久的要点。这样摘要可以随时间衰减而不必重写。
上游是跨调用累积，本适配器一次产完。

**baseline（基线）**
注入到每次请求里的那份固定内容：项目记忆、用户画像、全局域。它冻结不变，
新东西走增量车道，所以新记忆不会触发缓存前缀重建。

## 检索与向量

**FTS5**
SQLite 的全文检索扩展。分词器是 `porter unicode61`，与上游一致。它不切分中文——
整段连续汉字会被当成一个 token，所以中文查询基本只能靠向量通道。

**embedding（嵌入）**
把一段文本变成一组数字（向量），用来做语义检索。本插件默认在包内跑 MiniLM-L6，
384 维，不需要 API key；也可以换成 OpenAI 兼容的远程服务。

**tick**
插件的维护循环，默认每 30 分钟一次：TTL 归档、批量核验、向量回填、全域候选入队。

**parity（门禁 / gate）**
共享向量空间的一致性校验。首次写入时在内存里算一个样本向量，
和存储里的那条比余弦相似度；低于阈值就关掉向量通道、退回全文检索，
以免两套模型的身份混在一起。结论按进程记忆，重启后会重新校验。

**hybrid / semantic / fts**
检索结果的命中来源。`hybrid` 表示关键词和向量两条通道都命中，`semantic` 表示只有向量命中，
`fts` 表示只有全文命中。混合得分是 `0.7 × 余弦 + 0.3 × 倒数排名`，单通道结果乘 0.8 惩罚。

**importance（重要度）**
historian 为每段摘要打的 0–100 分。约束后续一切的决策在 80 分以上，改个拼写大约 3 分。
分档决定摘要用 p1 还是 p4 呈现。

## 界面

**H / Q<n> / N err**
遥测胶囊上的三个缩写，来自 `src/client/index.js` 的胶囊渲染：
`H` 是 historian 的首字母，后面跟它的状态（`H 运行中` 或 `H 空闲`）；
`Q<n>` 是 queue 的首字母加待落地条目数，`Q3` 表示队列里还有 3 条没落地；
有错误时 `Q<n>` 的位置换成 `<n> err`，表示最近有多少条错误记录。
窗口变窄时胶囊只剩 `H` 和队列后缀，再窄就只剩压力百分比。

**记忆（memory）**
插件自己 SQLite 库里的项目事实。项目身份从 git 根推导，跨会话保留。

**画像（profile）**
用户级的事实，比项目记忆活得更久。读取、收集、评审三个开关互相独立。

**全域（global domain）**
跨项目共享的记忆域。入队可以自动化，发布永远要人点。
