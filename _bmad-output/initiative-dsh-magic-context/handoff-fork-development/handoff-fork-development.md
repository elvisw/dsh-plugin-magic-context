## 4. 两个问题的准确含义

### #13：当前缺陷与两种可选契约

**已验证事实：**插件 `0.11.1` 的 `ctx_expand` 使用 surface replace，把原文恢复到旧位置，自己的工具回复只是状态确认。因此再次 reduce 同一 tag 有意义。第二次虽然显示 Queued，实际未落地；原文仍在上下文，并非丢失。存储层重新入队没有清空 `landed_event_seq`，记录被 pending 查询排除；源码与事件证据见 Issue 留档。

实施前由用户确认选择，结合作者最新反馈：

- **A，优先建议：结果返回。**独立读取历史，原文作为新的 `ctx_expand` 工具结果返回；旧节点保持已回收状态。新返回内容必须按正常机制获得新 tag，后续回收新 tag；重复 reduce 旧 tag 不应伪称重新排队。
- **B，兼容现有设计：原位恢复。**保留旧位置替换，修复重新入队的状态转换与幂等行为，并验证同一 tag 的多次回收/恢复。

两者不是同一个验收契约。不能用旧版的“expand 后再次 reduce 旧 tag”用例判定 A 失败，也不能只把该断言删掉就宣称修复。更改返回方式不会自动解决 #14 的历史定位问题。

采用 A 时，新工具结果有自己的消息/调用身份；保真校验应追溯原始来源和内容，不应要求新工具结果的 ID 等于旧节点 ID。

### #14：摘要后独立读取原文

**已验证事实：**全新会话只做首次 drop，排除了 #13 的 requeue 干扰。真实 Historian 发布摘要、遮蔽该占位符后，旧 tag 的 expand 路径不可达；原始事件仍在宿主日志。这是现有入口的能力边界，不是已经确认违反作者承诺。

**建议目标：**摘要发布后，通过受支持且稳定的定位方式读取原文，不依赖占位符仍可见，不要求一定用旧 tag，也不要求撤销摘要、重建旧位置或再执行原工具。

原版 TS 模式可按持久化 tag 索引定位；已核查的 Rust 模式拒绝 tag 查询，提供消息序号/范围路径。DSH 事件序号、原版消息序号和 tag 是不同标识。不要照抄编号或承诺所有模式都支持旧 tag；数据确实缺失时必须明确失败或降级。

## 5. 实施前先确定的验收条件

先写短方案，说明选择 A/B、定位标识、数据来源、兼容性和测试层级，得到用户确认后再实施。以下是拟议检查项，**不是已经通过的新功能测试**：

| 范围 | 应验证什么 |
|---|---|
| 原文保真 | 比较完整内容和来源身份；不得用重新读盘、重跑工具或模型重写冒充恢复 |
| #13 采用 A | 旧节点仍回收；原文在新工具结果中返回；新结果可按新 tag 回收；重复 reduce 旧 tag 的回执符合实际 |
| #13 采用 B | `drop → 原位 restore → requeue → drop → restore` 可重复完成，检查存储和宿主事件而非只看工具回执 |
| #14 的独立用例 | 全新会话首次 drop，确认 Historian 真正发布且来源包含该节点，再按实际支持的入口读取原文，核验摘要未被撤销 |
| 持久化与失败 | 退出/重启后仍可按支持方式定位；错误会话、无效标识和缺失数据不能返回别的内容或伪称完整恢复 |
| 影响范围 | 保持宿主工具配对、会话边界和受支持内容类型；未覆盖的二进制、多轮归档等如实声明 |

原验收使用 32K 加速窗口、降低阈值并禁用其他裁剪器，只证明该路径，不代表默认百万 token、多轮 Historian 或并发崩溃已经覆盖。新测试需披露自己的触发条件。

已有 `verify_acceptance.py` 校验固定旧证据，退出 0 不等于产品或新修复通过；`repro_requeue.mjs` 在未修改 `0.11.1` 上预期退出 1。部分脚本依赖原临时实验目录，不能直接搬到 fork 或换个版本运行就当成通用回归套件。先读 [REPRODUCE.md](../acceptance-windows-dsh-2026-11-09/REPRODUCE.md)，新实验另建目录，不覆盖旧记录。

## 6. fork 的工作规则与交付边界

下列规则来自当前 fork 的 `CONTRIBUTING.md` 和 `package.json`；接手时重新核对，并遵守作用域内的代理规则：

- 使用 npm，保留权威 `package-lock.json`；不要把实验 profile 使用 pnpm 的配置误搬到普通源码开发。
- `src/core/` 保持宿主中立，只有 `src/dsh/` 引入 `@deepseek-ai/*`；测试先表达行为契约，替身必须镜像真实宿主形状。
- 代码、注释和测试名用英文；文档按仓库中英文约定维护，用户文案同步两种语言。保留许可证、版权及第三方声明。
- 开发验证入口为 `npm run typecheck`、`npm test`、`npm run build`、`npm run check:i18n`；贡献指南要求 PR 前跑 `npm run gate` 或其允许的替代检查。此处只列现有入口，本次没有安装依赖或执行它们；接手时先检查测试和 gate 的实际副作用。
- 从确认的基线另开任务分支，不直接在 main 混合改动。两个问题可能共用恢复契约和定位层，先确认依赖，再拆分聚焦的提交或 PR；不机械要求二者完全独立。
- 不提交生成物、模型凭据、私人会话、真实记忆库或本机绝对路径。研究材料不必全部进入上游 PR；只带必要代码、测试及说明。
- 真实 DSH 实验必须隔离 config、会话库和插件数据库；仅继承凭据，不打印、复制或持久化。不使用日常 profile，模拟模型必须另行标注。
- 执行依赖安装、真实模型实验、Git 提交/推送、创建 PR、打 tag 或发布前，确认授权范围；本交接不包含这些授权。

若发现基线已修复问题，先报告差异，不重复实施。完成后分别报告做了什么、实际执行的检查、未覆盖范围与剩余风险；不能以证据校验成功代替产品修复验证。
