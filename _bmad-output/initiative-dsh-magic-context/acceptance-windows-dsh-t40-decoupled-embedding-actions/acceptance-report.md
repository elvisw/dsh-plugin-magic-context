# T40 验收报告：加载模型贴身、远程动作与保存解耦、撤销未保存更改

**结论：三项要求都在真实 DSH Web 宿主上验证通过** —— 隔离宿主 `0.2.2-rc.5` 上 51 步断言 0 失败、0 console error。

## 用户要求

1. 「请把`加载模型`这个按钮放到`模型 ID`这个框附近」
2. 「还有`保存并加载模型`，`保存并测试`这种功能上的耦合莫名奇妙，不要这么耦合，分开它们」
3. 「如果出现存在草稿未保存这种情况，但是用户不想保存怎么办，我觉得还需要为用户提供'清除草稿'的功能按钮，文案就写成'撤销未保存更改'」

## 改了什么

| 改动 | 之前 | 现在 |
|---|---|---|
| 加载模型的位置 | 卡片底部动作行，离它填充的字段很远 | `模型 ID` 字段旁的 `[data-mc-model-field]` 组里，与输入框/下拉框同级 |
| 有草稿时 | 按钮变成「保存并加载模型」/「保存并测试」，点击会先偷偷保存 | 只保留「加载模型」/「测试连接」，二者**永不写配置** |
| 有草稿时的可用性 | 可点（并隐式保存） | 保持可见但**禁用**，卡片显示「先保存当前修改，再执行远程操作。」 |
| 放弃草稿 | 只能关掉设置页，连其他未保存修改一起丢 | 状态栏后的「撤销未保存更改」，只清未保存修改 |

`测试连接` 留在动作行：它测的是整条远程链路（endpoint + 密钥 + 模型），不属于某一个字段。
