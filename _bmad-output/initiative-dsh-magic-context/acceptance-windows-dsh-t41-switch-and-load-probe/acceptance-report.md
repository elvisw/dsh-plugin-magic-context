# T41 验收报告：禁用原因写在按钮旁边 + 模型提示语说明操作顺序

**结论：报告的两个问题都已在本机隔离宿主上复现、定位并修好。** T41 gate 23 步 0 失败、0 console error；T40 gate 用同一批字节回归 51 步 0 失败。

## 复现结果（修之前）

用 `t41_probe.cjs` 在隔离宿主里按用户路径操作，只记录不修改：

| 阶段 | 加载模型 | 屏幕上的解释 |
|---|---|---|
| 本地 MiniLM（初始） | 不显示 | — |
| 切到 OpenAI 兼容（未保存） | 显示但**禁用** | 有，但写在卡片最底部；按钮在字段行里，读者看不到 |
| 保存之后（未配密钥） | **仍然禁用** | **完全没有** |
| 保存密钥之后 | 可用 | — |

所以「不起作用」不是一个原因，而是两个：

1. 切换提供方是草稿，按钮被禁用；解释离按钮太远（同一个卡片里，但隔着整列字段）。
2. 保存之后仍然禁用，因为还没配 API Key——而这条门槛来自服务端（`embeddingActionRefusal` 在 `keyMissing` 时拒绝列模型），界面上却没有任何说明。

## 改了什么

- 新增纯函数 `embeddingBlockReason(action, input)`，按读者能动手的顺序给出第一个阻塞原因：
  只读 → 有远程操作在途 → 迁移已暂停 → 记忆关闭 → 接口地址为空 → **未保存修改** →
  **未配置密钥** → 模型为空（仅测试连接）。
- 原因直接渲染在「模型 ID」字段行内（`data-mc-model-block`），同名文本同时作为按钮的
  `title` 与 `aria-describedby`（禁用的按钮不可聚焦，读屏改从字段侧念出原因）。
- 原因是「未保存修改」时后面跟一个**保存**按钮（`data-mc-model-block-save`）——读者主动点击的保存，
  不是 T40 否掉的隐式保存；表单无效时该按钮禁用，避免点了静默返回。
- 动作行的原因行改用同一套解析（`data-mc-actions-block`），不再只在「脏」时出现。
- 模型提示语改为：先点「加载模型」拉取服务商公布的模型 ID，再从这里选择；列表里没有的模型也可以直接填写。
